# N-PORT preparation and storage

N-PORT research uses the existing private, gzip-compressed Supabase disposable cache. It stores one complete parsed portfolio per ticker and SEC accession, plus a small `LATEST` reference. The reference contains identity, source-check time and the exact body hash; it does not contain another holdings table. The former `fund-research-v1` gzip/base64 manifests and chunks are neither read nor written by this loader. They expire through the existing cache maintenance policy.

The namespace is `edgar.nport-prepared.v1:production`. Both record types use the bounded document family and retain data for at most 30 days. A latest reference is at most 4 KiB decoded; a complete accession body is at most 24 MiB decoded and still subject to the shared 6 MiB compressed limit and document-family quota. There is no additional schema, public database access, permanent raw-file copy, per-filter record or per-comparison copy.

Interactive latest requests require a source check within one hour. Once that check expires, the loader verifies ticker/CIK/series/class identity and refreshes SEC submissions and the series-specific filing feed. An unchanged accession can reuse its complete parsed holdings; it does not download the XML again. A different accession or changed source metadata requires ordinary source retrieval. The original holdings `retrievedAt` remains unchanged when XML is reused. Only a successful metadata check advances `cache.checkedAt`. Exact historical accession requests can reuse the immutable report for up to 30 days.

`readPreparedFund(ticker, accession = '', { signal, allowStale = true })` reads prepared data only. It performs no SEC request and no directory lookup. Latest results older than one hour have `cache.stale: true`; source dates remain visible to the public research summary. After 30 days, or when a head/body identity or hash does not agree, the reader returns null. This reader does not trigger preparation or extend retention. Mutable shared heads are checked on each read so another server's publication is observable; locally held bodies are refreshed when the head hash changes.

Validation covers the requested ticker, CIK, series and class identity, SEC accession paths, filing/report/source dates, all holdings, unique row identities and the recomputed complete-portfolio summary. Signed, zero and unavailable values are preserved. Oversized reports are rejected with an original-filing link rather than truncated. Full holdings continue to serve search, filtering, exports, comparisons and historical changes.

Process memory is bounded by 32 MiB and 48 entries. Up to four distinct requests can be pending; identical requests share work. Source work has a 50-second deadline, a 40,000,000-byte XML limit and a 64 MiB cumulative response limit. Cache failures remain optional: successful validated source results can still be returned and retained locally. During a shared-cache transport failure, the latest local result is reusable only within its original one-hour freshness window. A successful shared miss or newer shared head takes precedence; a rejected conditional write does not authorize an older local replacement. Development and preview retain bounded local data without production cache access.

Tests cover 997-position preservation, latest/accession deduplication, stale prepared reads, cross-instance replacements, series mismatch, corrupt summaries and pointers, source-date preservation, optional cache outages, concurrency and the overall deadline. Existing N-PORT parser, workspace and comparison tests remain applicable.
