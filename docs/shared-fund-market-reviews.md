# Shared full 13F market reviews

The Funds Market connections tab opens a compact published snapshot directly, independently of the complete manager holdings report. **Review all holdings** starts one shared job for any supported manager and explicit reporting quarter. Starting a review saves the full verified report on the server; another visitor joins the same manager-quarter job. Neither a browser tab nor an individual user's session owns its progress. A compact manager summary supplies quarter choices in parallel. A missing publication remains distinct from an empty or complete review.

## Publication and freshness

Every disclosed position receives a status: queued, supported market connection, partial filing review, disclosure without a supported benchmark, no qualifying passage, no eligible filing, unverified issuer, or unavailable evidence. Finishing the report means every position has a terminal review status, not that every issuer or market connection could be established. Unavailable and partial attempts retry up to three times per cycle. The final state distinguishes completion with coverage gaps.

The database stores evidence separately from compact holding summaries. A publication contains prepared aggregates and the first fifty status rows, generated when the worker releases its claim. Opening a publication does not aggregate the full report again. A tiny progress read reports the current job and publication version; visible active pages poll it every fifteen seconds, with complete/paused jobs checked every sixty seconds. Only a changed publication triggers a new summary download. Filters and later pages remain bounded to fifty holdings; selecting one holding retrieves its original saved evidence. Percentages retain the full reconciled 13F denominator. They describe associated disclosed holdings, not economic exposure or the manager's futures positions. Incomplete public reports have no portfolio percentages.

Snapshot responses use a sixty-second CDN lifetime and up to five minutes of stale-while-revalidate. A new `version` query avoids waiting for the previous cache key to expire; it is a publication-change hint, not a historical revision selector. Evidence remains pinned to an exact report hash. An optional initial CFTC chart is attached only when already present in bounded server memory. A cache miss never delays the saved summary: a managed post-response task may read existing prepared chart data within three seconds, with at most four in-flight reads and a one-minute miss cooldown. It never starts a source crawl; the selected client chart can load independently. A bounded browser cache preserves return-visit content while checking for updates. Manager research pages render the same publication as HTML, with coverage, dates, supported benchmarks, and up to three original issuer-source examples.

A report hash binds the ordered holdings, quantities, values, completeness, denominator and actual filing chain. Source check timestamps do not alter that hash. The worker checks the selected report through the existing source freshness policy before each invocation; an amendment replaces the job revision and fences older workers. Completed jobs become eligible for a fresh review after twenty-four hours. Prior evidence remains readable with its original dates and stale labels while a new cycle runs or a source fails. When capacity is needed, completed reviews that were not explicitly requested for thirty days become eligible for cleanup.

The current discovery pointer retains its twenty-five-hour window. Immutable issuer documents, parsed ownership proofs, and extraction revisions can remain for thirty days within the existing document quota. Revisions bind the exact issuer, filing identity, source digest and extraction version. Freshness remains six hours for ready discoveries and current issuer assertions, one hour for no matches and fifteen minutes for missing filings. A due discovery checks current SEC submissions and bounded archive manifests before reusing an unchanged annual or quarterly document. Retrieval and extraction dates are preserved; only successful current checks advance check dates. Changed filings are downloaded, changed extraction versions are recalculated from saved text, and incomplete searches remain explicit. Storage eviction is a cache miss, never evidence that an issuer has no connection.

## Work and cost bounds

The existing signed five-minute SEC coverage schedule drains up to three review batches within 140 seconds alongside its normal work. This adds no scheduler or paid service. POST starts the same bounded drain after its response, using a deadline fixed when the request began so report preparation also counts toward its 150-second route limit. The drain hands the released lease to the next queued manager rather than ending after one batch. Idle queues return immediately without waiting or polling. All batches share a 120-dispatch SEC allowance; a later batch can still reuse saved research after that allowance is exhausted. Both paths compete for the same database lease, so only one shared review worker runs at a time. An adaptive batch can scan up to 2,000 pending positions and publish up to 1,000 results, within its seventy-five-second deadline and ninety-second fenced lease. Work pages contain at most 100 positions; source-free classifications and prepared results publish atomically in batches of at most fifty. Cold research uses at most sixty holding lookups, two source workers and 120 actual SEC dispatches including retries/redirects. These are ceilings, not guaranteed throughput. Reaching the local source allowance defers a holding without spending its failure retry. Prepared issuer lookups preserve validated hits incrementally, so one unavailable or slow cache lookup does not discard the rest of its batch. A new job with acknowledged cached filing evidence releases and publishes its first prepared batch before cold research; later claims resume the remaining holdings. Unsupported-security classifications alone do not trigger that early publication. Each acknowledged save survives an interruption; report identity is checked once per invocation rather than once per small work page.

Production limits admit twenty manager-quarter jobs, up to twenty thousand distinct holdings per job and eight MiB per frozen report. Result payloads are bounded to one MiB each, summaries to sixty-four KiB, and total saved result JSON to 512 MiB. Prepared publications add at most four MiB per job (eighty MiB across all twenty slots). A global daily allowance bounds processing to 14,400 reserved worker seconds and 6,000 saved attempts; an acknowledged early release returns unused seconds, while interrupted invocations retain their reservation. The existing SEC dispatch gate and Vercel spend cap remain in effect. These are workload limits, not a dollar-cost guarantee. A cold review of thousands of holdings can span multiple processing days, depending on source latency, retries, queue demand and the allowance. Available results appear progressively throughout.

## API and operations

- `POST /api/fund-13f/market-review` accepts only JSON `{ "cik": "0002012383", "period": "2026-06-30" }`. The server retrieves and validates the full report. Clients cannot submit holdings, source URLs, budgets or results.
- `GET` with `cik`, `view=snapshot` and optional `period` returns the saved publication and optional prepared initial chart. Omitting `period` selects the latest **saved** quarter, which can differ from the latest SEC quarter. `view=progress` returns only job progress and the publication version. Both are read-only.
- `GET` on that path accepts `cik`, `period`, optional `reportHash`, `market`, `status`, `query`, `offset` and `limit` (maximum fifty). GET never starts research. Public responses have a short shared CDN lifetime.
- `GET` with `cik`, `period`, `reportHash` and `key` returns one saved holding's evidence. Its exact report revision prevents mixing amendments.
- Private `edgar_private.fund_review_*` tables have RLS enabled. Only the production workload gateway can invoke the bounded service-role RPCs. Preview and browser credentials cannot mutate jobs. `EDGAR_FUND_REVIEW_MODE=off` disables the adapter; the existing CFTC switch also disables review APIs and workers.

Deploy the migration before the gateway and application. The `thirteenFReview` field in the SEC coverage response records bounded worker progress or deferral. Inspect job state, last saved timestamps, current-cycle terminal counts and the daily allowance when diagnosing slow progress. Do not restart jobs or remove SEC coordination to accelerate a backfill.

The kickoff uses Next.js [`after`](https://nextjs.org/docs/app/api-reference/functions/after), bounded by the route's duration. Durable continuation comes from the existing authenticated scheduler and SQL checkpoints, not an unbounded background promise.
